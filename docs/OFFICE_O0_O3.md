## 冻结规则
- engine 0.15.0 / content office-1；旧档明确拒绝，无猜测迁移。无办公室配置的历史内容继续使用旧硬件规则。
- 初始3套完整木桌/板凳/电脑、1块两席白板、1张咖啡台；补购基础套180，标准套550，基础升级补370。O0–O3只实现家具质量外观及升级交易，效率、恢复、摸鱼属于O4，界面明确说明。
- worker/tool占电脑，planner/reviewer占会议席；gpt.4o、claude.sonnet及website-phased阶段的支持岗位要求电脑。通过内容配置表达，不能按技能值猜测。澄清同样消耗相应设施一槽。
- 第0–4章电脑槽上限4/6/9/12/16，另有会议2槽、休闲3槽、设备2槽。白板每件2席。所有已分配任务working/review/waiting保留设施；未分配accepted不占；终止/完成释放。席位稳定保留，不因画面重排改变。
- 在用设施禁止移动、收回或升级；不自动抢占其他任务。休闲设施不占任务席。电脑套餐是完整三件套，单件拆装后续扩展；机柜首版仅外壳，算力/存储/网络仍通过原系统升级，不重复加成。
- 布置草稿只在宿主内存，停止推进时段；提交通过单个office Command原子扣款/保存，取消不产生Command。必须保留所有原有家具，可收回仓库，首版无出售退款。预设只重排已有家具，不购买。草稿revision过期拒绝。
- 使用拥有实体ID的家具库存，位置不等于所有权；新家具ID由核心分配，玩家不得伪造原有物品。无变化提交拒绝；重放重复提交拒绝。
- 原office硬件购买入口在新内容中由布置替代；本阶段新档office等级固定0，不提前引入O4效率倍率。

## 表现与验收协议
- 背景和家具共用1920×1080世界坐标及同一镜头；姓名/热区按屏幕可读尺度；三区镜头是空间聚焦，不再按角色分页。
- 家具后层/人物/家具前层按脚点深度排序，闲置家具常驻；纸娃娃复用原资产。四位开局角色走近→入座；离开任务走向休闲点。减少动态直接落位。
- 真实HUD开发夹具不访问IndexedDB/Host存档；固定种子与动画时间。覆盖初始、12人、工作、电脑要求、低精力、危机、交付回执，中文/英文/主题/减少动态。
- 视口390×844、680×900、1280×720、1920×1080、2560×1080检查布局、按钮可用、名牌；桌面和手机均可通过点选槽位操作，不依赖拖拽。
- 单测：跨任务容量、会议席、版本/模板覆盖、在用保护、非法命令状态/RNG/现金原样、预算不足、库存不复制、revision冲突、预估不改存档、保存恢复/完整回放。
- 经营原有10局属于旧版本证据，不据此宣称新版本经济平衡通过；O4–O6及后续内容保持开放。

## 复现

1. 在仓库执行 `pnpm dev:web`。
2. 打开 `http://127.0.0.1:5173/?office-lab=working&animation-time=1`。可替换为 `initial`、`twelve`、`computer`、`low-energy`、`crisis`、`delivery`。
3. `locale=en&theme=dark&motion=still` 可固定英文/深色/减少动态；不传动画时间时观察走近/落座。delivery夹具保留首条回执直到手动收起，正常经营仍自动消退。
4. 夹具仅在DEV启用；刷新丢弃内存档。正常游戏去掉查询参数，使用独立版本数据库。执行 `pnpm check`；`node scripts/create-office-art.mjs` 可重建原创家具。
