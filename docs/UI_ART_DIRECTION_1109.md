# UI / 美术复审、定调与完善计划

日期：2026-11-09。审查基线：0c41339 及其未提交工作树。本文为本轮实施决策；不重写 GDD，不改变 engine 0.16.0 / content office-2 的经济与存档规则。

## 1. 结论与范围

**方向接受，完成度不能按“Phase 1–3 全量落地”验收。** 暖色材质、主行动实心化、纸面弹窗、家具软阴影和工位预估强化解决了真实问题。CSS 换皮不能代替组件体系，染色不能代替光照融合，测试通过不能代替全角色全场景视觉验收。

审阅包括未提交的 UI_ART_REVIEW_1109、UI_ART_FIXES_1109、27 个已修改文件及审查截图，并参考仓库外 ../docs/design_scope_1109 的两份原始讨论。原讨论中的用户选择继续有效：3 套开局、180 补购、支持岗位按情况需要电脑、确定性摸鱼结合发现提醒、初期固定槽位。其旧 HUD 占位图、“绝不遮挡”“天然向后兼容”等推论不再作为实施依据。源码与当前 OFFICE_O0_O3 / OFFICE_O4_FIRST_LOOP 优先。

原 UI_ART_REVIEW_1109 是针对 0c41339 的历史只读报告；其截图不是本轮修改后的证据。报告中的 P0 是视觉优先级，不等于数据损坏或崩溃级缺陷。没有证据支持“与大型商业二次元游戏同等完成度”，只采纳其层级清晰、一致性与反馈原则。

## 3. 冻结的设计方向

### 3.1 题材、材质与角色

定位为 **温暖、轻松、略带科技感的现代 AI 工作室经营游戏**。情绪来自共同工作与逐步改善环境。保留 AI Village 原版12名角色身份、服饰、骨架与授权来源；背景与家具向角色的简化细节靠拢，避免用统一灰黄滤镜抹掉身份色。

- 背景：暖自然光、柔和材质、明确可用地板；背景中的吧台/机柜等为建筑装饰，不冒充可交互设施。后续新背景将“装修固定件”和“购买实体”分层设计。
- 家具：现代木质办公家具，圆润体块、轻描边、三段明暗、左上主光、接触阴影。继续使用可维护 SVG 生产线，先证明一个完整样板角落统一，再决定是否需要手绘纹理；不全量替换成不可控生成贴图。
- 角色：现有 scale/headY 是逐角色视觉校准，不能称为头身比归一化证明。以可见身体 bbox、眼线、坐姿脸部遮挡共同验收；头饰与尾巴不作为身体等高依据。
- 环境色：本轮一次性轻暖 tint 是基线；后续按场景与时段设置统一环境参数，暗场不牺牲脸部明度。禁止每个骨骼层累乘染色。
- 地板锚点保持(0,0)，前/角色/后遮挡层与共用1920×1080世界相机保留。不能为了画面漂亮删除可购买实体或更改可工作容量。

### 3.2 工位等级与玩法表达

| 等级 | 冻结剪影 | 机制口径 |
|---|---|---|
| 基础 / Tier 0 | 小木桌、简单木椅/凳、旧单屏，无灯带与装饰堆叠 | 已实施：工作精力额外+2，产出无加成 |
| 标准 / Tier 1 | 整洁暖木桌、网布椅、单屏；小型桌灯/绿植作次级差异 | 已实施：执行/负责人WP +10%，按实际产出计资源；不写成Tier II |
| 高级 / Tier 2 | 升降结构、更完整人体工学椅、横竖双屏 | 仅视觉预留；价格、效率与摸鱼概率需独立规则验收 |
| 豪华 / Tier 3 | 更宽围合桌面、曲面屏/多屏、明显高端椅型 | 仅视觉预留；不提前卖无效果数值 |

标准工位上的 +10% 是岗位相关产出加成，不能表达成所有角色的速度、质量或稳定收益。预估为条件预测；结算后另给实际结果。精力预警使用图形+文字，闪电仅作视觉提示，<35 是 UI 提醒阈值，不改变领域疲劳规则。服务器外壳明确无算力效果，摸鱼/休闲恢复当前未开放。

### 3.3 UI 视觉规范

- 三种材质：常驻 HUD 深胡桃半透明胶囊；抽屉/模态高不透明象牙纸面；布置工具深胡桃工具面。保留全屏世界和按需浮窗，普通开窗不改变镜头。
- 黄铜用于边框、选中与小面积强调；鼠尾草绿表达正向收益；危险红表达风险。不能只靠颜色传意，普通木色材质不能承担所有状态编码。
- 当前 tokens.css 是运行时颜色源：--paper、--solid、--primary-bg/--primary-ink、--fs-*。文档不再维护另一套虚构 token 名。后续删除重复局部值时逐组件回归，不能一次性用通配覆盖。
- 正文14–16px，说明12–14px，11px限于非关键标签；价格、风险、操作结果不得用11px。标题现用系统楷/衬线回退为过渡方案，正式字体需有许可、中文/英文覆盖、离线加载与体积记录后再纳入。
- 主行动实心、一个区域一个主行动；次行动描边/纸面，危险行动含明确文字。主按钮不得仅用透明文字。全部控件都有默认、悬停、键盘焦点、按下、选中、禁用、忙碌与错误状态。
- 保留语义化原生 select/details/meter，先统一外观与交互。仅因“原生控件像网页”就重造下拉框不成立；自定义版本必须先证明键盘、读屏、触控和长列表体验不退化。
- 动效120–180ms，状态转换可观察，禁用动画时信息仍完整；不引入反复闪烁与无意义漂浮数字。

### 3.4 布局与手机策略

桌面以场景为主，抽屉按需显示。手机采用“场景局部观察 + 区域切换 + 伙伴列表定位”，不把12人强行缩进390px。当前 cover 导致手机首屏看不到部分工作角色，是明确遗留；下一阶段对工作区与选中对象的聚焦补齐，并提供返回全景。普通弹窗继续不移动相机。

槽位布置继续是固定锚点；显示选择器作为键盘与裁切兜底，支持收起工具。不要承诺所有家具与浮窗永不重叠；验收的是可找到、可选中、可取消、可保存，以及关窗后可看清世界。

## 4. 进入后续开发的详细计划

以下工期为单人集中实施估算，按验收结果调整。每一步独立检查点，未通过不扩大量产。

| 阶段 / 预计工作量 | 具体任务与产物 | 依赖 / 放行标准 |
|---|---|---|
| A 样板冻结 / 1–2天 | 交付车库工作角落样板：基础/标准桌、Qwen/DeepSeek/GLM三种体型、空闲/走近/坐下/离座、亮暗时段；输出视线、桌面、地板锚点标注与升级剪影表 | 本轮修复后开始；脸与关键手部不被屏幕挡，腿部切换自然，桌下不悬空；明确主光后再批量改其他家具 |
| B UI组件收敛 / 2–3天 | 梳理 style.css/studio-ui.css/village-ui.css 覆盖关系；提取按钮、标题栏、预估卡、风险提示、空/错误/忙碌态；修复所有44px触控目标；登记字体与图标规范 | A材质冻结；中文/英文与明暗主题同布局；键盘闭环、关闭后焦点恢复、禁用操作原因可读；字号和对比度实测记录 |
| C 相机与布置 / 2–3天 | 手机工作区默认焦点与人物定位、重置全景；安全区、横屏工具条、长文回流；按章验满工位/会议/休闲/设备布局；将槽号转为玩家可读名称，内部ID只留诊断 | A几何与B控件；390/560/680/1280/1920/2560及844×390；无横溢、主要按钮可达、收起工具后边缘槽可操作；不改变普通弹窗镜头 |
| D 美术生产 / 3–5天 | 按样板精修8类家具的前后层；逐角色记录bbox/眼线与坐姿校准；逐章背景检查并输出原生高清/适配构图，不以插值放大冒充细节提高 | A与C通过；12人/全章满配置遮挡矩阵完成；生成器可重复输出，来源/许可/尺寸/加载成本齐全 |
| E O4机制反馈 / 2–3天 | 先补现有工位/精力的完整状态图例，再实施O4-B摸鱼与发现提醒的状态机、回执和点击入口；O4-C恢复另切片 | B/C后；概率/代价/未发现与发现的时序先写规则；纯核心确定性，预估/结算/回放/保存与UI一致，表现动画不得采样玩法随机 |
| F 性能与交付 / 1–2天 | 分场景懒加载、测PNG解码与GPU纹理峰值；失效资产占位与重试；离线缓存升级测试；减少动态/200%字体/无blur降级；整理新截图和运行日志 | D/E后；约定目标机后实测帧时间与内存，首轮数据建立预算，不虚构60fps；离线重启可继续，资源加载失败仍能操作 |

执行顺序 A→B→C→D；E可在B/C后独立推进，不等待所有高清背景。F记录数据并决定优化，不用观感代替性能证据。O5工作台在B组件基线后推进，O6遵循F。仍开放的M05-03与历史经营验证不因美术通过而关闭。
