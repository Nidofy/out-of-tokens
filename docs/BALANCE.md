# M0平衡协议与诊断记录

## 冻结协议 v2（进入未见种子前）
引擎0.3.0，内容m0.3-1。调试种子1–100；正式验证用1001起的1000个未见种子，每策略60天，破产提前结束但仍保留该局和完整分母。
5策略共用公开可行性约束：预估质量>=63，产出×期限>=工作量×1.15，角色空闲/精力合法，不读取结算随机流。
- value：最大化每角色每标准工作时段报酬，扣除Token成本估计；长期合同计入14工作槽的占用。
- greedy：优先最高预估质量和产出；不优化成本/长期占用。仅属性贪心，M0没有闭源旗舰。
- random：打乱可接受委托顺序，在同一公开约束内的队伍中均匀抽样。它是“可行集随机派遣”，不是无约束随机动作；此定义必须与报告一起审查。
- no-clarify：value策略关闭澄清；其余调度和事件选择一致。
- clear-only：value策略只接清晰度>=80委托。
所有策略默认选第一个可负担事件选项；不自动借贷/加班，不拿这些功能给策略加额外补贴。玩家可自行使用。

## 指标
净现金流=最终现金-5000；第14天记录现金和是否破产；入账旧债后的负现金不等于立刻破产，因此同时报告偿债后现金非负率，不用“0破产”掩盖欠费。
交付/违约率分母为接受单数，并另报未终结订单。小白违约对照只以已终结小白单为分母，避免不同未结算比例偏差。
角色参与率=实际付费服务时段占比，分执行/审查/负责人统一计入；四个已解锁角色均需覆盖。
云Token与本地算力分列。项目利润：终结项目的预付款/尾款/违约净额，减临购T消耗成本、电费、目标事件成本、按实际quota占比分摊的已结周订阅费。办公室租金、继承旧债、贷款融资不混入项目毛利。
CSV提供逐局指标，JSON提供完整参数/内容指纹/参与率/项目明细；报告保存诊断回放。

## 验收门禁
按GDD§16.8及初始化Prompt的M0修订：value第0章破产率<5%；random在60天窗口破产率40–70%；value四角色实际参与率各>=3%；已终结小白单中no-clarify违约率>value的2倍，且两组各至少30笔已终结样本。
正式旗舰毛利约束和12角色覆盖延至M2（D010），本轮只报告属性贪心毛利比作诊断。
未通过不得标M0.5完成；验证之后若改规则/策略/参数，须另换未见种子队列重新验证。

## 保留的失败轨迹
旧M0.2：25局60天，四策略100%破产/greedy80%，见历史SHA与m0-slice日志。
扩充内容后原全员单队20种子：value30%、greedy95%、random100%；value遗漏长期合同等待占用成本。
修正占用成本后调试100种子：value4%、greedy93%；无约束random仍100%。
探索随机组队角色数量、审查岗位、澄清对照后，无约束随机依然100%；其失败主要是选明知能力不足的队伍和无利润的占用。
随后明确采用共同可行性过滤的random v2，不把早期结果混入正式v2报告；调试100种子random44%，value4%。这属于策略定义变更，需外部复核，不能声称改善的是同一个random策略。
调试时未加硬编码胜率、按seed补贴或改变破产条件，且没有靠删除失败局达标。
