# Productization A2：可解释的派遣与交付

2026-11-07，依据 GDD §14.2–14.4 与 GPT-6 review 的 A2 核心决策界面、A3 精选内容规划。本阶段为可运行检查点，不代表第0章精品体验全部验收。

## 已实现

- 派遣方案显示当前阶段完成时点、工作时段数、云端/本地资源预算、本地电费、条件质量范围及逾期/状态/资源/隐藏需求风险。
- 预估是纯函数：不读取或推进RNG，不修改输入状态，不记录命令。短任务按剩余工作量截断；原模拟支持岗位的保守预算门禁保持不变。单槽资源不足风险仍按门禁所需上限判断。
- `settlement` 是核心结算与ViewModel共用的来源：评级、倍率、逾期衰减、预付款、现金净变动、返工/交付可用性。基础失败原因对所有玩家可见，细分技术报告仍由 explain 软件提供。
- 交付成功反馈本阶段实际现金变化。看板显示真实小数进度，不把33.x/34显示成34/34。
- 委托分为进行中、待接单、已结束，可搜索标题；原有无截断列表保留。账本与事件效果改为玩家术语，未知账本来源显示“工作室收支”，不显示内部ID。
- GDD §5.4四位初始伙伴的独立双语介绍。只描述角色定位，不暗示未实现的特性加成。
- 12份委托双语编辑：menu、bugs、website、signup、backup、weekly-script、translation、speech、story、newsletter、review、survey。明确客户线索、工作范围与现有策略取舍；隐藏需求具体化，机械参数不变。website明确尚无谈判缩单，避免文案承诺不存在的机制。

## 预估边界与设计决策

冻结当前精力、心情、饥饿压力和负载；假设资源持续足够、不发生新事件/缺陷/返工。未来只在正常工作时间执行，不自动延续当前加班；上限112槽（28天）。这里只预测当前阶段，长期合同不把未来各期收入提前算入。

质量区间是上述条件下的基础值±5，并钳制0–100；不是成功概率或可信区间。实际事件、缺陷和状态变化可使结果超出区间。当前版本尚未按管理软件提供不同精度，也未支持自动补购、多人多单争用资源的全工作室预测。不得据此声称GDD预估系统已完全实现。

云端T是游戏额度消耗，不重复扣现金；不估算未来免费配额和补购。电费按新增本地用量0.1/单位显示，周结收取。UI文字明确这些假设。

engine仍为0.11.1：结算公式提取与只读预估不改变既有规则；内容版本升至m5-3，以区分新的委托文案与内容指纹，旧内容存档仍明确拒绝，不猜测迁移。
