### S-01 | P2 | 15e2775 | apps/sim-cli/src/console.ts:50（配合 packages/oot-core/src/simulation.ts:203,214）

- **问题**：explain() 的错误映射在两类输入错误下给出误导文案。
- **复现**（固定 worktree 实测）：
  1. 首局资金 ¥5000 时输入 `buy 0` → 输出 `操作失败: 资金不足 [INSUFFICIENT_CASH]`。实际原因来自 `requireRule(cmd.amount > 0 && s.cash >= cmd.amount * 0.5, 'INSUFFICIENT_CASH')` 的 `amount > 0` 分支（simulation.ts:203），并非缺钱。
  2. `accept 0-1` 后输入 `assign 0-1 ghost:worker:cloud` → 输出 `操作失败: 角色正在执行委托或澄清，请推进时段或换人 [ACTOR_BUSY]`。实际是角色 ID 不存在：`requireRule(a && !occupied(...), 'ACTOR_BUSY')`（simulation.ts:214）把「找不到角色」与「被占用」合并为同一错误码。clarify 同一代码路径。
- **影响**：玩家被引导去推进时段、换人或凑钱，而真实修正是改输入；M0 的验收点是「完整决策信息 + 中文错误」，这类反指会直接误导新玩家。M1 Web 宿主若复用 explain() 会放大。
- **最小修复**：core 拆分错误码（如 `POSITIVE_AMOUNT_REQUIRED`、`UNKNOWN_ACTOR`），或在 CLI 层先校验（amount===0、角色在 status 列表中）给出准确文案，explain() 补两条映射。保持原状态返回不变。
- **阻塞依赖**：无（建议 M1 前修复）。

### S-02 | P2 | 15e2775 | packages/oot-core/src/simulation.ts:127,131-132 对照 :271

- **问题**：经济规则常量在结算与展示两处硬编码双写：周结 2300（:127 与 :271 `nextWeeklyBill`）、旧债 8000（:132 与 :271 `debtDue`）、到期槽 56（:131 与 :271 `debtSlot`）、及格线 60（:233,:245 与 :271 `passQuality`）。
- **复现**：修改任意一处常量，另一处不变，`pnpm check` 不会失败；玩家看到的「下次周结预计¥2300」可能与实际扣款漂移。
- **影响**：STATUS 已把 B01（改 bot 选人 + 逐项目成本统计，经济调参）列为下一任务，正是最可能动这些数字的时机；展示层漂移属于静默错误，且现有测试只断言具体数值不校验两处一致。
- **最小修复**：oot-core 导出 `WEEKLY_BASE`、`DEBT_AMOUNT`、`DEBT_SLOT`、`PASS_QUALITY` 常量，结算与 ViewModel 共用；加一条测试：构造已知 electricity 的状态，断言 `nextWeeklyBill === 实际周结扣款额`。
- **阻塞依赖**：无；建议并入 B01 顺手完成。

- **阻塞依赖**：无。
