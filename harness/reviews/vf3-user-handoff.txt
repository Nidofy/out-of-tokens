  1. **局部错误与弹窗内动作在手动关窗后泄漏到 S1**：`presentation-events.ts` 第 15 行无条件返回 `return open.modal ? null : 'global'`。实机在 `?office-lab=initial` 打开 Qwen 档案 → 展开「能力、版本与成长」→ 点「研发 ¥600 / 10RP」产生局部错误 `"现金或研发点不足。"`（`target: {surface: 'actor', id: 'qwen'}`, `error: true`）→ 点右上角 `×` 关闭 Qwen 档案后，该角色局部错误会跳到 S1 底部的 `.status-toast` 常驻显示，且之后每次打开/关闭地图或其他弹窗回到 S1 都会重新挂载 `<p role="alert">` 触发重复播报；同理在 S3 点击「去找伙伴」（`visit`）关窗后 S1 也会弹出无上下文的 `"安排好了。"`。
  2. **弹窗开启期间发生自动保存失败（`StorageFeedbackError`）或跨标签冲突（`EXTERNAL_CHANGE`）被隐身及覆盖抹除**：`use-game.ts` 中 `StorageFeedbackError` 与 `EXTERNAL_CHANGE` 均将 `target` 设为 `{surface: 'global'}`。当 S2 或 S3 处于打开状态时，`feedbackSurface` 对 `surface: 'global'` 返回 `null`（导致 `hosted`/`desktop` 下弹窗内操作写盘失败时弹窗不关闭且界面无任何报错）；而在 Web 模式下，若 S2/S3 开启期间触发 `onExternalChange`（`paused.current = true`），玩家在关窗前随手点击弹窗内任何不写盘的常规动作（如 `accept`、`clarify`、`chat`、`meal`），新的成功回执会直接覆盖 `feedback`，导致玩家关窗后也彻底看不到 `EXTERNAL_CHANGE` 警告。
- **最小修复要求**：
  1. **禁止局部反馈在关窗后串入 S1**：在 `presentation-events.ts` 的 `feedbackSurface` 中，当 `open.modal` 为 `false` 时，仅当 `feedback.target.surface === 'global'`，或属于显式关窗回执（如 `feedback.receipt?.kind === 'assign' || feedback.receipt?.kind === 'deliver'`）时才返回 `'global'`；对于 `target.surface === 'actor'`、无跨屏收据的 `'job'`（如 `STILL_CLARIFYING`、`accept`、`clarify`、`scope`、`reject`）以及 `'saves'` 的局部反馈，在对应弹窗关闭后返回 `null`（或在关闭 `jobId` / `actorId` 弹窗时清理属于该局部对象的错误/回执；对于 S3 内的「去找伙伴」`visit`，直接走场景切换或不在 S1 遗留 `"安排好了。"`）。
  2. **确保全局存储错误（`StorageFeedbackError` / `EXTERNAL_CHANGE`）不被弹窗隐身或被非写盘成功回执静默抹除**：
     - 当 `feedback.target.surface === 'global' && feedback.error`（如 `EXTERNAL_CHANGE`、`AUTO_PAUSED`、`STORAGE_UNAVAILABLE`、`SAVE_CONFLICT`、`WRITE_UNCERTAIN`）时，若当前打开了 `job`、`actor` 或 `saves` 弹窗，`feedbackSurface` 应允许在当前活动弹窗的 notice 区域（`job` / `actor` / `saves`）直接展示该全局存储错误，使玩家在弹窗内即可立即看到写盘/跨窗口告警；
     - 同时在 `use-game.ts` 的 `report` / `send` 中，若当前存在未关闭的全局存储错误（`feedback?.target.surface === 'global' && feedback.error && paused.current`），未执行 `write('auto')` 的普通命令成功回执不得静默覆盖该全局存储错误（直至玩家手动点 `×` 收起、或通过 `load`/`importFile`/`reconcile` 解除 `paused.current`）。
